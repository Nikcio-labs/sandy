Isolated compute.
Not an isolated copy of your project.

Docker Sandboxes use microVMs, not ordinary containers with access to the host Docker socket. Sandy manages local sandboxes through sbx; it is not a cloud management console.

Mounted project folder: the same files, read and written directly.

The folder you attach is real

Edits in a directly mounted workspace change your host files immediately. The microVM boundary does not protect that folder from the agent.

Stop is not delete

Installed packages, agent state, and in-sandbox files survive stops and restarts. Removing a sandbox deletes its internal contents, not the directly mounted host folder.

No folder is also a choice

A mountless sandbox has no host workspace bind mount. Its files live inside the sandbox and persist until removal. Other explicitly configured host access still applies.

A quiet workbench.
A clear boundary.

The sandbox boundary is the memorable motif. Everything around it stays practical: left-aligned type, one shared list, restrained selection, and controls sized for repeated use. No invented CPU charts, uptime, or “secure” scores.

Friendly, not decorative

Gabarito gives names and headings a rounded, human character. System sans handles controls; monospace appears only for real commands, paths, and YAML.

State is earned

Running and stopped are classified exactly as in the app. Other CLI labels keep their text and use inactive styling. Pending verbs describe work in progress, not a new CLI state.

Motion answers an action

120ms press feedback. 180ms dialogs. 220ms nested panes. No motion for search, row selection, keyboard actions, or polling. Reduced motion removes movement.

Two requirements.
Everything else can wait.

A proposed first-open simplification: install sbx, then sign in to Docker. SSH belongs with editor connections; image paste is optional host access. Neither should hold up your first sandbox.

Start with your project, not a checklist.

Docker Desktop and Docker Engine are not prerequisites for sbx. Local sandboxes do need supported hardware virtualization. Agent authentication and model-provider charges are separate from your Docker sign-in.

This replay is simulated. It never opens a sign-in page or installs software.

Small details. Real consequences.

Use the demo controls to put the design under pressure: a failed start, a saved template whose launch fails, an empty list, and a missing CLI. Recovery is part of the design.

Keep the last known state

A failed refresh leaves existing rows visible. Retry repairs the error without replaying the list entrance.

Save succeeds. Launch fails.

The template remains saved. Retry launch does not create a second template or erase the user’s choices.

Connect without extra setup

The native terminal uses the CLI directly. SSH is only needed when you choose an editor connection.
